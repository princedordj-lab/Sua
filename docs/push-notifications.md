# Push notifications

Two transports, one server module:

| Client | Transport | Credential stored |
| :--- | :--- | :--- |
| Android app (iOS compiles, untested) | Expo Push Service | `push_tokens.token` (ExpoPushToken) |
| Web (`/app/*`) | Web Push + VAPID | `web_push_subscriptions` row (endpoint + keys) |

`backend/src/lib/push.js` owns delivery for both. `notifyUser()` reads the
student's rows, sends, and deletes credentials the provider reports as dead
(`DeviceNotRegistered` for Expo, `404`/`410` for Web Push). Every send is
best-effort: a push failure never fails a job or a request, and the network
calls happen outside `withUser` (its transaction times out at 15s).

## What gets sent

- **Study set ready** - `pipeline.js` calls `notifyUser` when a job finishes.
  Deep links: mobile `/note/<id>`, web `/app/note/<id>`.
- **Daily review reminder** - web only. `lib/reminders.js` runs from the jobs
  tick, counts due flashcards per student with reminders on, and pushes once
  per day. `/review` (mobile) and `/app/review` (web).
- **Test** - `POST /api/me/push-test` proves the credential chain without
  waiting for a generation.

Mobile schedules its own daily reminder locally (`expo-notifications`, per
device, works offline), so the server reminder deliberately targets
`transports: ["web"]` to avoid double-notifying a student holding both.

## Mobile (Expo Push)

Opt-in only: nothing asks on launch. The student turns it on in
**Profile -> Notifications**, which runs channel -> permission -> token and
pushes the token to `POST /api/me/push-token` with `platform`.

Requirements for a working build:

1. **Expo project id** - already set in `Sua/app.json` (`extra.eas.projectId`).
   `getExpoPushTokenAsync({ projectId })` needs it.
2. **FCM credentials** - create a Firebase project with an Android app whose
   package name is `com.pdordj.Sua`, then:
   - download `google-services.json` into `Sua/` (next to `app.json`);
   - add `"googleServicesFile": "./google-services.json"` under `expo.android`
     in `Sua/app.json` **at the same time**. The config plugin throws during
     prebuild if the key points at a missing file, so the key and the file land
     together - never one without the other;
   - upload the FCM v1 service account key to Expo with
     `npx eas-cli credentials` (Android -> Push notifications), which is what
     lets Expo's service reach Firebase.
3. **A development or release build** - push is unavailable in Expo Go on
   Android since SDK 53. Use `npx expo run:android` or an EAS build profile.
4. The notification icon (`assets/images/icons/notification-icon.png`, 96x96,
   all-white, generated by `tools/make-notification-icon.mjs`) and the tint
   colour (`#005B45`) come from the `expo-notifications` config plugin.

Opting out deletes the device's token server-side and clears the local
`expo_push_token` setting, which is also what suppresses the local "study set
ready" banner (`lib/generate.ts` -> `announceReady`), so a device with a token
is notified by the server only.

## Web (Web Push)

1. Generate the VAPID pair once, in `backend/`:

   ```bash
   npx web-push generate-vapid-keys
   ```

2. Put the keys in `backend/.env` (`VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`,
   optional `VAPID_SUBJECT`) and the **public** key only in `web/.env.local` as
   `NEXT_PUBLIC_VAPID_PUBLIC_KEY`. Without the server pair
   `GET /api/me/push-status` reports `web: false` and the settings page hides
   the toggle instead of offering a button that cannot work.
3. Deploy `web/public/sw.js`. `next.config.ts` serves it with
   `Cache-Control: max-age=0` so a fixed worker is never stuck in a browser
   cache, and the Clerk proxy matcher already skips `.js` paths, so it stays
   public.
4. `app/manifest.ts` provides the install manifest (192/512 icons from
   `web/tools/make-pwa-icons.mjs`). Installability is what makes iOS
   notifications possible: iOS 16.4+ delivers web push **only** to a site added
   to the Home Screen.

The page is `/app/notifications` (linked from Profile and Preferences). It
toggles the browser subscription, saves the reminder preference
(`PATCH /api/me/notification-settings`), and can send a test.

Web Push needs a secure context: `localhost` works, a LAN IP needs HTTPS.

## Reminders and the cron

`GET/POST /api/internal/jobs/tick` calls `sendDueReminders()` after the job and
extraction passes. On the Hobby plan Vercel allows one cron per day
(`0 6 * * *` in `backend/vercel.json`), so `reminderTime` is a target, not an
exact minute:

- default - the reminder goes out with the daily tick; `lastReminderSentAt`
  keeps it to one per 20 hours;
- `REMINDERS_EXACT_TIME=1` - only send once the student's local time has passed
  `reminderTime`. Set this only with an hourly cron (Pro);
- `REMINDERS_ENABLED=0` - skip the sweep entirely.

A zero-due day still stamps `lastReminderSentAt` (so the tick does not recount
all day) but sends nothing: reminders never say "nothing to review".

## Data

Migration `18_push_notifications`:

- `push_tokens.platform` gains a default (`android`) - the route had always
  required the column but never sent it, so registrations used to fail;
- `web_push_subscriptions` - one row per browser, `endpoint` unique so a shared
  browser that signs into another account re-owns its subscription;
- `notification_settings` - one row per student, drives the web reminder.

All three cascade from `users`, so account deletion removes them, and each has
the same RLS policy shape as the rest of the schema (scoped through
`users.clerkId`).

## Checking it end to end

1. `npx web-push generate-vapid-keys` -> backend + web env -> redeploy both.
2. Backend: `npm run build`; apply the migration with
   `npx prisma migrate deploy`.
3. Web: sign in, open `/app/notifications`, turn the toggle on, press "Send
   test notification". A blocked browser reports "Notifications are blocked"
   instead of silently pretending to be on.
4. Android: `npx expo run:android` (dev build), turn on in Profile ->
   Notifications, then `curl -X POST $API/me/push-test -H "Authorization: Bearer
   <clerk token>"` and expect `{"delivered":{"mobile":1,"web":0}}`.
